#+TITLE: План первой рабочей версии Roded
#+DATE: 2026-10-03

* Цель и источники истины

Довести ветку =1-architecture= до рабочего редактора с curses и Qt frontend.
Обязательный продукт и критерии завершения заданы в =GOAL.md=.
Горячие клавиши: =docs/keybindings.md=. Qt: =docs/qt-frontend.md=.
Основание пересмотра: =docs/architecture-review-2026-10-03.md=.

Одна общая editor session, произвольное число buffers, split windows/view
с независимыми point/mark; frontend выбирается при запуске.
Оба frontend реализуют полный обязательный сценарий через общий core.
Физический viewport/layout принадлежит frontend; текст/point/mark/history — core.
Поддержка одновременного Qt+curses и нескольких desktop frames пока не нужна.

Это исполнимый план, а не перечень новых классов. Завершение этапа означает
работающий сценарий и проверки. Имена EditorState/FileService/FrontendManager
можно уточнить, если ответственность и контракт сохранены.

пока не покрыты. На ревизии specs проходят, RuboCop сообщает 70 offenses,
=bundle exec rake= возвращает ошибку. State/services/views ещё не выделены.

* Правила выполнения и коммитов

- [ ] После каждого законченного этапа обновлять этот план и validation log.
- [ ] Основные этапы коммитить отдельными осмысленными коммитами с imperative
  subject; крупный этап разбивать на меньшие проверяемые коммиты.
- [ ] Перед коммитом выполнять затронутые specs и lint, проверять diff.
  После начала реализации все specs должны оставаться зелёными. Существующий
  lint debt не увеличивать; временный точечный baseline только с описанием.
  К завершению убрать временный baseline и добиться green =bundle exec rake=.
- [ ] Не смешивать одновременно перенос state, File IO и Qt UI в один коммит.
- [ ] Не отмечать пункт выполненным по одному mock expectation или skeleton.
- [ ] Заканчивать обязательные функции и проверки без запросов продолжения
  после каждого уже согласованного этапа. Существенный scope change согласовать.
- [ ] Не включать посторонние пользовательские изменения и не переписывать
  историю ветки. Push/PR/release этим заданием не запрошены.
- [ ] Сохранять review как исторический документ; актуальные доказательства
  писать в =docs/working-editor-validation.md=, не переписывать старые результаты.

* Этап 1 — P0: устранить подтверждённые поломки и стабилизировать runtime

- [ ] Quit устанавливает stop state core, не ждёт обратный Event(:quit) из UI.
- [ ] Routed C-x C-c и M-x quit проверены с настоящим event loop и timeout.
- [ ] Системные signal/EOF/failure обрабатываются независимо от focus.
- [ ] Shutdown/wake/join/close и восстановление signal handlers имеют ensure;
  ошибка команды не оставляет terminal в raw mode или живые input workers.
- [ ] Пустой файл редактируется; Buffer сохраняет допустимые строки/позиции.
- [ ] Open/save сохраняет final newline и поддерживаемые LF/CRLF/UTF-8 данные.
- [ ] Specs проверяют ошибку IO, runtime exception и очистку ресурсов.
- [ ] Создан validation log; lint debt зафиксирован/сокращён без blanket disable.

Критерий: baseline + регрессии из review проходят; lifecycle завершает run,
file roundtrip не теряет текст. Коммит этапа до широкого рефакторинга.

* Этап 2 — P1: общий core contract, session/views и публикация UI

- [ ] Разделить InputEvent, EditorCommand и UI update; сохранить source/view id.
- [ ] Pending key sequence хранится по независимому input stream.
- [ ] Dynamic key sequence resolution поддерживает C-x/C-c/Meta и user prefixes;
  cancel/invalid sequence имеют явное поведение.
- [ ] Ввести единый реестр/контракт команд для keys, M-x и Ruby API.
- [ ] Выделить editor state/session; handler не зависит от всего Application.
- [ ] Определить Buffer text/history и EditorWindow point/mark/active buffer;
  логический window tree принадлежит session, physical geometry — frontend.
- [ ] Перенести cursor ownership из Buffer с сохранением существующих scenarios.
- [ ] Контролируемый edit API не отдаёт изменяемые live lines/cursor наружу;
  инварианты readonly/positions соблюдаются на каждом входе.
- [ ] KillRing обновляется из edit result, Buffer не получает KillRing dependency.
- [ ] Единая публикация UI-state заменяет observers/direct-render/broadcast mix;
  insert/backspace/delete/newline продолжают перерисовываться.
- [ ] Frontend получает initial active view/minibuffer/picker state при подключении.
- [ ] Cross-thread snapshots независимы и immutable; ядро — single writer.
- [ ] Geometry policy использует именно активный source/view и учитывает overlays.
- [ ] Core загружается без require curses/qt; launcher подключает выбранный adapter.
- [ ] Проверить два input streams, late frontend, два view одного buffer и edits.

Критерий: headless core управляет views/commands; rendering имеет один путь,
ввод источников не смешивается. Миграция этого этапа — несколько коммитов,
сохраняющих запуск curses после каждого законченного подшага.

* Этап 3 — P1: ранний работающий Qt slice

Не откладывать совместимость с qt до завершения всех features.

- [ ] Проверить опубликованный/installed qt gem и local API по =docs/qt-frontend.md=.
- [ ] Probe реальных events: key/text/modifiers, consume, resize/focus/close.
- [ ] Проверить доступные text/cursor/selection/highlight APIs используемой сборки.
- [ ] QApplication и widgets в GUI/main thread; выбрать явную runtime интеграцию.
- [ ] Один buffer: Qt input -> core edit -> UI snapshot -> рабочее отображение.
- [ ] Super test binding вызывает core command ровно один раз; Alt/Super различаются.
- [ ] Close/exception не вызывают widgets из чужого потока и не зависают.
- [ ] Qt dependency/CLI boot воспроизводимы без обязательного local absolute path.
- [ ] Missing bindings обходить локально; каждый hack получает TODO(qt): HACK
  и запись с API gap/reproducer/test/normal replacement в qt-workarounds.md.

Критерий: рабочий вертикальный сценарий с реальным Qt, а не только doubles.
Сохранить probe evidence и отдельный коммит интеграции. Полная parity — этап 9.

* Этап 4 — P1: надёжный файл и полноценный edit model

- [ ] Выделить FileService с results/errors; core принимает решения и prompts.
- [ ] CLI file arguments, find-file/new file/save/save-as/cancel/dedup paths.
- [ ] Safe save, permissions/symlinks, overwrite и внешние conflicts.
- [ ] Modified revision, saved state, save/discard/cancel при kill-buffer/quit.
- [ ] Undo/redo для всех обязательных edits; grouping и paste transactions.
- [ ] Mark/region, kill/copy/yank/KillRing и readonly на всех edit entrypoints.
- [ ] Unicode position transforms корректируют point/mark всех views на edits/undo.
- [ ] Word/document movement, tabs/indent, multiline paste и длинные строки.
- [ ] Headless integration open/edit/save/close/quit и failure/cancel cases.

Критерий: файл можно безопасно редактировать и сохранять без потери данных,
undo и modified state согласованы. FileService и edit history — разные коммиты.

* Этап 5 — P1: окна и usable curses frontend

- [ ] Scratch/startup, Emacs-подобный dark UI, modeline и echo/minibuffer.
- [ ] Switch/next/previous/kill buffer в активном окне, одинаковые basenames различимы.
- [ ] Horizontal/vertical split, other/delete/only window; последний view сохраняется.
- [ ] Один buffer в двух окнах: общий текст, независимые point/mark/positions.
- [ ] Viewport follows point с горизонтальным scrolling; page size из text area.
- [ ] Custom line/page scrolling с явно определённой core/view policy.
- [ ] Resize/small screen, prompts/picker overlays, сохранение active view.
- [ ] Robust input decode: function keys, Meta, Unicode, prefixes, paste, EOF.
- [ ] Default/native UI rendering нигде не меняет domain model.
- [ ] Удалить/переопределить console Window/StatusBar и пустые wrappers.
- [ ] Первый реальный PTY/curses smoke: несколько файлов, split, edit, save, quit.

Критерий: основной file/window scenario выполняется в настоящем TUI.

* Этап 6 — P1: общий picker, поиск и справка

- [ ] Переиспользуемый picker model/provider API, live orderless filtering и history.
- [ ] Providers: commands, buffers, file paths, project/root files, lines, KillRing.
- [ ] Navigation/accept/cancel, empty/Unicode candidates, list scrolling/resize.
- [ ] Preview отменяется с восстановлением исходного view/buffer/point.
- [ ] C-s line search, forward/backward search, goto-line и query-replace.
- [ ] Help/describe-bindings отображают actual user keymap и зарегистрированные commands.
- [ ] User keymap validation, prefix hints и минимальные custom commands из таблицы.
- [ ] Проверки всех providers, query edit, cancel/replace и layout interactions.

Критерий: нужный файл/buffer/команда/строка выбираются в живом UI, поиск и
replace обратимы. Provider/history/preview не становятся curses-only logic.

* Этап 7 — P1: независимые modes и syntax highlighting

- [ ] Plain text fallback и modes по filename, ручная смена mode.
- [ ] Ruby/JSON/YAML/Markdown token spans и theme mapping.
- [ ] Multiline/incomplete Ruby и изменение tokens после edits/undo.
- [ ] Rendering spans не изменяет text/history/point/modified state.
- [ ] Tokenizer errors не рушат loop; geometry Unicode и highlights согласованы.
- [ ] Проверены реальные curses colors, region/search и monochrome fallback.

Критерий: обязательные modes дают полезную устойчивую подсветку.

* Этап 8 — P1: встроенный programmable Ruby REPL

- [ ] Persistent in-process binding, multiline input, history и *ruby* buffer.
- [ ] Results/stdout/stderr/exceptions отображаются без повреждения UI.
- [ ] Инспекция реальных state/buffers/views и документированный mutation API.
- [ ] Edits из REPL идут через core, поддерживают undo/readonly/modified и все views.
- [ ] Register command/binding из Ruby, запуск через M-x и клавиатуру.
- [ ] Simple long evaluation interrupt, exit из REPL, exception recovery и cleanup.
- [ ] Нет competing state owners или вызовов GUI из REPL worker.
- [ ] Примеры Ruby API в README проверены; исходники qt live IRB — reference,
  отдельный external IRB вместо доступа к живому state не считается выполнением.

Критерий: из UI можно изменить живой editor и увидеть/отменить результат.

- [ ] Общие commands, file flows, region/undo/search/modes работают как в curses.
- [ ] Native text/undo/context menu не образуют вторую editor model.
- [ ] Mouse focus/caret/selection/wheel и clipboard идут через core contracts.
- [ ] Unicode core/UTF-16 Qt offset conversion, tabs/long lines/scroll/resize.
- [ ] Все обязательные Super/Menu aliases из таблицы, включая Alt+Super/punctuation.
- [ ] s-Left/s-Right resizing split и configurable combinations.
- [ ] Native close -> save/discard/cancel; отмена сохраняет рабочее desktop window.
- [ ] UI-thread/snapshot/feedback-loop/REPL/shutdown integration checks.
- [ ] Real-widget offscreen tests + desktop smoke с физическими Super keys.
- [ ] Список hacks полон; TODO сообщает missing API и требуемую замену в qt.

Критерий: сквозной acceptance scenario из GOAL выполнен в Qt, зафиксированы
